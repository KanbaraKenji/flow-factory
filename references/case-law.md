# flow-factory 判例（append-only，带日期）

来源：2026-10-18 ~ 10-21 洗版流水线样机 v1 → v16 的十几轮用户批注（样机 https://claude.ai/artifact/8ibBRw1sriYsXpr8NAznWQ）。每条写「现象 → 根因 → 规则」。

## 2026-10-18 生产线比竖向单线好
- 现象：v1 竖向单线、每个岔路都让人选，用户评「不实用，岔路太多」。
- 根因：岔路是代码的事，人想看的是「货怎么流」。
- 规则：整张画布一个平面，线、共用站、成品库、写入目标同时可见；岔路按结局归类挂在站卡下方，不逐个让人选；样例货按各自条件自动跑。

## 2026-10-18 好看是被看的前提
- 用户：「好用但不好看就没人愿意了解」。
- 规则：默认浅色亚克力 + 深色自动跟随；颜色全部走令牌，换风格只改令牌。

## 2026-10-20 按钮少而归类
- 现象：画布上按钮越加越多。
- 规则：播放类进底部图标栏；缩放与看全图和小地图拼成右下角导航器，按钮钉住不随小地图出现而移动；「操作说明」在页头；与页面无关的配置（带子流动动画）做成配置项不上画布。

## 2026-10-20 跟踪 = 缺氧式
- 用户点明：点货即跟踪、拖动画面即离开（缩放不算）、准星回到跟踪，就是《缺氧》等模拟经营游戏的成熟做法。
- 规则：画布交互先去游戏里找先例；跟踪钮放在每张样例货卡片色块正下方，全页只有这一种入口。

## 2026-10-20 时间推进要能后退
- 规则：走一拍左边配退一拍，快捷键逗号 / 句号；状态由拍数推出，后退是精确回到那一拍。

## 2026-10-20 工具画出来之后要回答「然后能干什么」
- 现象：寻路只画线，用户问「画出来以后能干什么」。
- 规则：任何工具的结果都要落到用户能用的结论或动作上（条件清单、风险点、派一件货走一遍），做不到就写明原因，不给点了才报错的按钮。

## 2026-10-21 研发图和监控图是两个概念
- 用户原话：「跑过和没跑过的概念放到待办单里面……这个视角是系统完成后发布后，我们定期审查系统是否有异常 bug 用的……目前我们在设计的是研发阶段的工作流程图。」
- 规则：研发图只读代码，视图只有流程 / 写入 / 故障，颜色只表示要不要关注；跑没跑过、流量、实际卡住的单属于监控图（第二阶段），数据格式预留 `runs`。

## 2026-10-21 用户第一眼把红黄当成「有问题」
- 现象：第一次试用故障视图，用户看到黄红就去点，点开只看到「出错去哪」，「不知道下一步该干嘛……看不出是什么原因导致的」。
- 规则：颜色就该真的表示问题——中性 = 设计好的兜底，黄 = 有隐患，红 = 没处理 / 卡死 / 收不回缺保护；出错种类改用文字标签。每条出错去向写三行人话：什么情况、你会看到什么、AI 的判断和建议。
- 例：「对应不唯一」按「下一轮再试」处理，下一轮也好不了、一直停在旧文件且没人知道 → 判有隐患，建议转人工并提醒。「重试」对用户不直观，叫「下一轮自动再试」。

## 2026-10-21 页面里直接反馈
- 用户：「直接在 html 针对具体问题做反馈，用户复制贴回 session 就可以进行反馈。」
- 规则：每条出错去向与每站都有「反馈」：三选一（这是问题 / 这是设计好的 / 我没看懂）+ 一句话 → 生成带图名、版本、站点、条目键的文字，一键复制；浏览器拦下复制就选中文字让人手动复制。

## 2026-10-21 文字显示完整
- 现象：条件文字被截断加省略号。
- 规则：面板里的条件文字整句换行，不加省略号，右侧标签顶对齐不挤正文；站卡上放不下的站名由校验器在构建时拦下（≤ 8 字），不在画面上截断。

## 2026-10-24 写成通用 skill
- 用户：「接下来我们要在实战中慢慢打磨这个 skill……验收标准是，尽量让人可以可视化了解一件产品或者一个工作流程，是怎么从数据输入到成品的全过程。」
- 规则：数据与画法分离——AI 只填 flow.json，坐标全部自动算（每行站数按画布宽高比挑）；「从输入到成品」用三处表达：页头「输入 → 成品」、站点面板「进来 → 出去」、被跟踪样例货头顶实时显示它当前的样子 + 面板逐站轨迹。

## 2026-10-24 第一轮实战试用（三个子代理：RC 看门狗 / AI 视频工作流 / 此瞬练琴后端）
- 结果：三张图都是读代码到出图 7~8 分钟、第一次构建 0 错误；读代码顺带查出 7 / 13 / 8 个真实问题（主会话抽查 4 条全部属实：钩子认值守会话只认写死的目录；值守失败不论原因都计次；ntfy 推送失败被吞、接口照样回已发送；关键帧模式重跑把挑好的首帧覆盖回第 1 候选）。
- 现象 → 规则（v0.2 已改）：
  - 几段工序前后相接只能拿岔路跳线头，正常交接被画成出错同款虚线、还误报「没写 product」→ 线加 `then`，画实带。
  - 「记成匿名」「校验有错照样放行」「占位字送进下游」不属于再试 / 转人工 / 中止 / 卡死，被硬塞成「中止」意思正好相反 → 出错种类加 `degrade` 带病放行，走过它的样例货标「带病」。
  - 流程视图的「失败」小标是红色，违背「研发图的颜色只表示要不要关注」→ 流程视图结局小标一律中性。
  - unhandled 判 ok 却仍显示「未处理」，与「不用管」自相矛盾 → 显示「无出错口」。
  - 写入小标放不下静默丢掉、成品库说明溢出卡片，校验和自检都没发现 → 放不下显示 +N；成品库说明多行；自检新增「成品库与写入目标文字在框内」「播放栏在首屏内」；校验提醒 desc ≤ 30 字、写入目标名 ≤ 10 字。
  - 写入目标一行比站点网格还宽，决定了全图缩放，22 站时字只有 5~7 px → 写入目标按网格宽度折行；全图缩放小于 0.42 时首屏对准第一条线入口并提示可拖动 / 看全图。
  - 旁站被放到整条蛇形最底下，离送货站很远 → 旁站放在送货站所在行下方。
  - 多进程 / 浏览器与后端 / 模型执行看不出谁在干 → 站点 `actor`、`kind: "ai"`；A 写 B 读的交接 → `reads`；定时循环 → 线 `trigger`；扇出 → 线 `per`；一站多个收不回动作 → `irreversible` 数组。
  - 拼错的字段被静默丢掉 → 校验器按白名单提醒未知字段。
  - 有隐患的岔路大多没有样例货走到，人看不到它出事 → 校验器提示覆盖率，SKILL 要求挑最要紧的一两条造样例货。
- 暂不做（记下等再遇到）：扇出后汇合的样例货（fan / join）、公共中间件站（每条线都经过）、`verdict.ref` 引用别站判断、同一步的两个入口（脚本版 / 界面版）`alt`、跨轮计数器 `state`、请求边界标记、回到本线前面站的回环单独样式。

## 2026-10-24 晚 用户审核第一轮（看了两份就不想往下看）→ v0.4
- 用户原话（摘）：「第一眼没办法看到全流程，目前卡片的排列太散了，不好看」「货物太多看着好乱」「站点描述的文字太多了，我看了几份后就厌烦了，基本进来实际要看的就是岔路内容……删掉无意义的 AI 味叙述」「连接线现在看着还是很乱」。
- 规则：
  1. **首屏看全图、方方正正**：所有卡片同尺寸落在一张网格上（成品库也占一格），写入目标不进流程 / 故障视图（只在写入视图出现），去掉画布上的线名标签（线名进图例）；首屏先全图约 1.4 秒，再把镜头推到入口开演。
  2. **一次只演一件货**：演完自动下一件（连播可关），底部左侧菜单选演哪件；第一件必须是走通全程的那件；没走到的站压暗。
  3. **文字主次分明、精简、去 AI 腔**：面板 = 站名 + 一句话 + 岔路（一行一条，出错的点开看「你会看到 / 判断」）+ 收不回的动作单独一节 + 折叠的次要信息；校验器给 when 14 / does 24 / user_sees 24 / note 48 等字数上限并提醒 AI 腔词。用户例子：「模型回的是能解析的 JSON」→「收到能解析的 JSON」，「每个空槽都填上且自检通过」→「自检通过」。
  4. **连线平时淡、走到才亮**：岔路和退回默认透明度 0.12，当前货走过的和鼠标指着那一站的进出线才亮；同列上下相邻的站直连。
- 三个子代理精简后一致指出「删短会丢依据」（为什么判红、把握多大、出处、规模、数值参数、静默副作用）→ 加可选 `station.detail` 与 `verdict.why`（不计字数，只在点开 / 折叠区显示）：首屏精简，依据还在。ok 级 note 写一句为什么不用管，risk / bad 写建议。

## 2026-10-25 用户审核第二轮 → v0.5
- 「演完停留 10S 后自动播放下一条」→ 连播间隔 10 秒，演完提示「10 秒后演下一件」。
- 「换一件出事的货，应当从起始点重新演示」→ 根因：拖动画面会关掉跟随，换货时镜头不回入口。规则：换货一律重开跟随、镜头回入口、从第 0 拍演。
- 「红色的站……请从排版和语义色入手，帮用户理清思路和看到应该看的重点」→ 出错条三层：条件一行 + 标签另起一行；展开后「你会看到」普通字 →「判断」→「建议」按严重程度着色的色块（全条最醒目的东西就是要你做的事）→「依据」默认收起；ok 级的理由放在灰色块里叫「理由」。
- 「连线重叠、莫名其妙的拐弯」→ 走线规则：同一卡边多条线的入口按另一端横坐标排序均匀摊开；每条行间通道、每道列缝按条分道（错开 9 / 8px，横跨长的先占中间道）；相邻两行之间只走中间那条通道（不再先去别的列缝再拐回，即截图里的回头弯）；跨多行时走目标卡靠起点一侧的列缝，路线单向。

## 2026-10-25 用户第三轮 → v0.6
- 「让 skill 自己判断应该有多少经典货物，或者判断无需有经典货物，自动播放会直接深度优先遍历播放所有路线」→ 页面自算「全部路线」（DFS，规则见 data-format.md samples 节，上限 60）；`samples` 改可选；`build.py` 数路线并给建议：≤ 12 条不写样例货，> 12 条写 3~6 件；不写样例货时「需要补」覆盖率按全部路线算。菜单分三组：典型样例 / 全部路线 / 我收藏的，连播只在组内轮。
- 「用户用演练模式（自己选路）可以记录收藏当前货物的路径」→ 演练走到头可「收藏这条路线」（localStorage `ff:saved:<标题>`，只在本机）或「复制成样例货」（`【流程图样例货】` + JSON，贴回对话由 AI 加进 samples，人人可见）。
- 「这笔钱我们拍板过闸线这个方案吧」（重申决策 #10「决策做成扳道岔」，此前附言「数字的摆放位置请帮忙设计的好看一些」）→ 演练时岔路口每条去向线上、离路口约 58px 处挂数字键帽，彼此不足 30px 就沿线错开；停在本站的结局不画到别处，从卡左下角垂一根虚线、键帽竖排、结局文字放键帽右边（横排时长标签互相压字，实测 RC 图）；键帽和结局文字按严重程度着色；悬停 = 那条线加粗 + 目标卡虚线框 + 选项板同条高亮；点键帽 / 点选项 / 按数字都走。⚠ 键帽反白时只反白键帽本身，结局文字不能跟着变白（第一版漏了，选中那条文字消失）。
- 「连线好很多但还是不完美」（截图：同列上下的线拐了弯、底部一条线和另一条虚线并排跑）→ 同列上下相邻且入口对齐的线一律直下；横段贴着它连的那张卡走（离卡 12px 起、每条 12px 一道，横跨短的贴得最近），不再全挤在行间通道正中和别的线并排。
- 「12 条以内不写样例货这个我觉得不要限制在 skill 内，让调用的 Agent 自己判断。我的 SKILL 提供的是方法和建议」（同日，推翻上面那条的 12 / 3~6 门槛）→ build.py 只报事实（全部路线几条、最长几步、自动播放会演什么），不再按条数发提醒；SKILL.md 第 2 节第 4 步改成「不写 / 写几件各适合什么情况」的判断方法，件数不设上下限。规则：**本 skill 给方法和建议，不给硬门槛**——数字阈值只在会让页面坏掉时才进校验器（如字数上限防卡片截断），属于取舍的一律写成判断依据交给出图的 Agent。
- 「选路选项重叠了」（截图：AI 短片「分镜自检」的 1 和 3 叠在一起）→ 根因：三条岔路（0 个错误 / 只有提醒 / 有错误）都去「选定分镜」，走同一条线，键帽按「沿线错开 26px」避让，而两卡之间只有 56px，错不开。规则：键帽按线分组，每条线只算一个落点，同线的几个键帽以它为中心、垂直于线每隔 30px 并排。

## 2026-10-25 用户第五轮 → v0.7 站内小流程
- 「卡片内部还有『小流程』那个设定，跟我们选路的功能性质是一样的，所以要定一个规则：多复杂的判断才要进小流程演示，什么程度允许在外面直接选路」→ 用户批准的方法：站内每个出口 = 外面一条岔路（外面选路看结论，站内一步步走看结论怎么来的）；进站内的信号 = 判断要走好几步 / 站内步子各自会出错要人关注 / 多线共用 / 多条岔路去同一处只差站内处理；留外面的信号 = 一句话说得清且各去各处 / 选项少 / 站里只做一件事。信号合起来看，不设门槛。契约（出口与外面岔路双向对上、站内不停住不进成品库）是硬的，进校验器。
- 「自动播放默认不进站内」（用户裁定）→ 样例货某一步写 `in` 才进去演，演完回到外面接着演；点站卡「站内 N 步 ›」随便看；演练到该站按 0 进去自己选，走到出口自动回来，这一步记下站内路线。
- 实施中自己发现的：① 故障视图底行要放出错标签，「站内 N 步」挂在底行会把它们挤掉——改成流程视图挂底行、写入 / 故障视图挂中间行（执行者让位）；② 外面看不到站内的隐患——故障视图里「站内 N 步」按站内最要紧的一级着色，面板写「站内 2 站有隐患」；③ 「分镜自检」三条岔路同去一处，按信号该考虑进站内，但它是平铺的一张检查清单、中间不分流，按方法留在外面，只修键帽重叠。
- 「站内三步的盒中盒设定与之前的 artifact 不一致，请重新优化」→ v0.7 做成了换层（整张画布换成站内、左上角面包屑、站卡底行「站内 N 步」），丢了 10-18 洗版样机已定的盒中盒。按样机改回：站卡右上角「站内 ›」是门；进去时镜头连续推进那张卡（外层快照按 1/缩放 放进站内坐标，镜头同步换算，画面不跳），卡的边框变成墙，外层淡化留在四周；左墙入口写从外面哪几站进来，底墙一排出口门，每扇门 = 外面一条岔路，站内出口岔路画成接到门上的带子；点门 / 点盒外 / Esc / 缩小 / 顶上居中的路径条（同心方块几层画几个）都能出来；外面的播放进去时暂停、出来接着放。盒子按卡片长宽比补足，多出来的高度上下平分，出口门跟着底墙走。规则：**已经在样机里定下的交互，做进 skill 时照原样实现；要改先说明差别再改**。

## 2026-10-25 夜 用户第六轮（通宵自迭代）→ v0.8

## 2026-11-26 第一次真实项目（业务流程图）：切站错两处
- 场景：一个样品制作开单系统（业务系统，Python 后端 + React 前端），画「一张单从开单到结单怎么走」，给外地工程师和主管的说明会答疑用（汇报配色投影 + 演练单步走）。观众不是开发者。
- 错误一：把「料号检查」单独画成一站。它是工程师点「提交」那一刻系统当场做的检查，人没离开开单页，货没换手。使用者原话：「应该是开单里面的内部流程，但是你现在把他单独成了一个站」。根因：skill 没定义「什么算一站」，出图的 Agent 按代码函数切（三个独立校验函数 → 一站）；`kind: gate` 的说明「闸门（会拦货）」像是在邀请系统检查单独成站；`inner` 的适用信号写的是「判断要走好几步」，一步检查对不上。
- 错误二：把 QE、IE、样制三方并行审核合并成一站「三方审核」。使用者原话：「三方审核应该是三个站点，但是你现在合并成一个站点」。根因：格式里没有「几方同时处理、都通过才往下」的结构（串成三站会变成有先后，`split/join` 是拆货不是会签），加上汇报风格「放不下时把同一角色连续的几步合成一个节点」，合并成了阻力最小的做法。
- 规则：① 一站 = 货换了一次手，或者有人要等；同一个人同一次操作里系统当场做完的检查、取号、存库、发通知，都进站内；几个人各自处理同一件货是几站，不合并；把站名念给流程的主人听，他说「这不算一步」的就不是站（SKILL.md 第 2 节）。② 定范围先问「这张图给谁看」（`summary.reader`）：给开发者按模块切，给使用流程的人按角色与交接切，代码函数边界不作数。③ `gate` 只给独立运行的把关（定时任务、另一个进程、另一个人）。④ 只有一步的当场检查也进站内。⑤ 汇报风格的「合并节点」只限同一角色的连续几步，不同角色、并行几方不合并。⑥ 校验器两条提醒：执行者写了几个角色（check / hand 站）→ 问是不是几站；系统闸门紧跟在入料或人工站后 → 问是不是上一站的站内检查。只提醒不拦，因为确有例外。⑦ 会签结构（groups）补上，见同日下一条。

## 2026-11-26 业务流程图用起来别扭的几处（第一次真实项目，同一份反馈）
- 「故障」这套词不适合规则关卡：20 条岔路全是规则本身（驳回、退件、缺料不能过），对外投影时「故障」「转人工」「有隐患 0」都不对 → 顶层 `vocab: "rule"`：视图叫「关卡」，小标按货被拦到哪写（退回修改 / 退回发起人 / 不能继续 / 回原站 / 转「某站」），不显示关注等级，面板「判断」改叫「说明」。数据格式不变，只换叫法（选了反馈里的方案 A，不另开 gate 说明块，免得同一件事两种写法）。
- 没有「待部署」的站 → 站上 `planned`（true 或一句说明）：点线框（不用虚线，人工站已经是虚线）+「待上线」小标，样例货轨迹里也标，图例可一键淡化。没做「一键隐藏并重排」：拿掉中间一站会让带子断开，淡化足够看出「现在线上的样子」。
- 一站几个角色放不下 → `actor` 可写数组，卡上第一个加「+N」。但几方各自处理是几站，数组只给「一站里几个角色一起做」。
- 对等的两条业务路被迫分正常与出错 → 站上 `decide: true`：几条岔路平时一样亮，不标「正常」。
- 汇报配色下 13 站染了 10 站 → 站上 `highlight: true` 优先；都没写时人工加检查站过半，就只给检查和闸门上色。
- 例行通知邮件被要求标成收不回的动作 → 分两档：对外造成后果的发送（扣款、对客户或外部单位的正式通知、上传）才是 `irreversible`；每站都发的例行通知写进 `writes`。判断法：发错了要不要有人出面收拾。
- 字数上限没写全 → `build.py --limits` 打印全表，SKILL.md 的表补齐（actor、样例货 desc / badge、成品库 desc、写入目标名、every、入口名、标题）。
- 看全图偏一边、字小 → 原来看全图左边固定留 230 像素给入口那件货的说明字，图被挤到右边；改成只留说明字实际要的宽度（70~230）。选列数时把成品库那一格也算进去。看全图字小的根本原因是站多、画布是 16:9 而图偏高，这个没法只靠缩放解决：站数 15 以上投影前用 `layout.cols` 或「只演这条流程」。
- 规则：**业务流程图和代码图共用一套数据，差别放在叫法和少数几个开关上，不另起一套格式**；新开关都是可省的，不写就是原来的样子。

## 2026-11-26 第五种结构：几方同时处理、都通过才往下（会签）
- 来源：样品单系统里 QE、IE、样制三方同时审同一张单，都通过才制作，任何一方都能退回；分厂没有 IE，跳过 IE。出图的 Agent 只能把三方并成一站（看不出是谁退回的），或排成先后三站（画出来像有顺序）；split / join 是「一件货拆成很多份」，也不对。
- 规则：数据上写 `groups`（组 id 进线占一个位置，成员是完整的站、只属于组）；成员通过写 `to: "next"`，可能不在的一方写 `optional`，一方退回后其余几方写 `on_return`（只影响动画和说明，去向都按退回那一方；几方同时退回按组里靠前的那一方）。样例货组这一步写 `each`。
- 页面上组是一个「虚站」，岔路由几方拼出来（都通过 / 跳过某一方后都通过 / 某一方某条不通过的岔路），所以路线、演练、结局、寻路都不用改；只有布局、带子、货的动画、面板认得它是几方。规则：**新结构先想能不能变成已有概念的一个实例，只在真正不同的地方（画法、动画）分叉**。
- 布局：几方的卡竖排在组那一格，按网格间距上下展开（所在那一行整体往下挪，卡片仍同尺寸、落在网格上）；分叉 / 汇合那一竖段贴着卡（离卡 12px）走，通道里的道位离卡至少 20px，不会和别的带子并排；组只从上游一侧进、下游一侧出。改了布线框的算法后，用旧版和新版渲染器各算一遍所有现有图的卡位和带子坐标，逐张比对完全相同，才算没回归。
- 动画：货到组时分成几份同时走（共用一段主带后再分开，各自到卡里），都通过时几份同时到汇合点再并成一件；镜头跟着几份的中心走。汇报主题里最后一方的说明字写在卡正下方，所以组的两行标题都放在框顶。
- 全部路线：DFS 规则「同一条岔路一条路线里不走两次」会让「退回开单」的路线在开单那里走不下去、整条丢掉；只对组的退回加一条：走不下去就停在「退回」（结局「退回『开单』」）。原有的图路线条数不变。

## 2026-11-27 对外投影前的一轮（第二次真实项目反馈）
- 来源：出图的 Agent 用 2f406c6 重画了那张业务图（13 站、1 个会签组、vocab rule、skin report），下午要对外投影，看图的是流程的主人。还在成品 HTML 上手改了好几处，要求改成正式写法。
- 叫法没盖全：vocab: rule 只换了视图名和小标，「入料 / 加工 / 出货」「成品库」「样例货」「岔路」「货的样子」还在 → vocab 可写对象逐词覆盖（kind / product / cargo / sample / branch / trigger），rule 默认就不出现「货」「成品库」。做法：作者的数据经 esc 时包一对私用区记号，写进页面前只替换记号外面的界面文字；页面里写死的按钮、页签、提示在启动时过一遍。规则：**改叫法只改界面，绝不改作者写的站名、条件和样例**；新加的界面文字照常写，这一层会替它换。
- 对外的图只要「流程」一个视图，开发者入口要能一次关掉 → views 白名单 + audience: public（寻路、对比、操作说明、反馈、代码位置、复制成样例货）。

- 会签组框顶的话写死了（「都通过才往下」「一方退回其余照常」），这个流程叫「驳回」→ 组可写 labels.rule / labels.on_return；不写时「退回」一词从各方不通过那条岔路的 when 里取（驳回 / 退回 / 否决 / 拒绝 / 打回，都没有就说「不通过」）。组面板里「（只影响动画和说明，去向都按退回那一方）」是写给出图人的实现说明，删掉。规则：**面板和画面上的每一句都要问一遍「看图的人用得上吗」，实现说明只进代码注释和 data-format.md**。

- 站内 6 个停住出口的结局字挤成一排互相压住 → 短桩错行：越靠左的桩越长、字越往下，字从桩右侧开始写，右边的短桩够不到左边那几行字。

## 2026-11-27 会签组补两处：都通过后去不同地方（pass）、整张单的去向（组自己的 branches）
- 来源：真实使用者画样品单审核。① 首次审核三方都通过 → 派单；改单后重审都通过 → 不再派单，直接回「制作」（原制作人、原交期不变）。组的「都通过」只能去线上下一站，只好在「派单」上加一条假岔路直接放行，画出来像派了两次单。② 审核途中工程师可以撤单，这不是任何一方的结论，只能挂在 QE 身上，显示成「QE：工程师撤单」。
- 根因：组只把「几方的结论」拼成去向，没有给「都通过之后看情况」和「整张单自己的动作」留位置；出图的 Agent 只能借别的站或某一方的岔路凑。
- 规则：都通过分情况写组的 `pass`（每项一个去向，样例货那一步写 `pass` 选哪一种）；不归哪一方的写组自己的 `branches`（字段同站的岔路，样例货那一步写 `br`，不写 `each`）。页面上 pass 的去处从几方的汇合点岔出去；组自己的岔路写在框底「整张单」一条、带子从框底中间出去，货不分份。条目键 `all/k`、`all~成员/k`、组岔路的 k。不写这两个字段的图，卡位、带子坐标、路线条数、SVG 输出与改前逐字节相同（新旧渲染器各算一遍全部正常图比对）。
- 通则：**用户为了凑出想要的去向而加假站、假岔路，或把东西挂在不属于它的人身上，就是格式少了一个位置**；补字段，不教用户绕。

## 2026-11-27 演练的选项板挪进右侧栏
- 用户：「路径选择的选项放在中下部分也很容易挡住我们的主画面，建议移动到右侧栏展示」。
- 做法：选项板（含「从哪个入口开始」和走完时那张）放进右侧栏最上面；侧栏本来关着就为它打开，离开演练（退出、换一件货）再关上，本来开着的不动。镜头不再把站推到选项板上方，而是放进「左边线路图、右边侧栏、下边播放栏」围出的空地，组就是整个框，放不下才缩小。手机上侧栏是底部面板，等你选路时只放选项板，样例货和站点面板先收起。
- 规则：**会长时间停在屏幕上的操作面板放侧栏，不浮在画面中间**；镜头取景一律扣掉线路图、侧栏、播放栏三块。
